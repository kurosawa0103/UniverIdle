# 冗余梳理：说明与模板

在 **删代码、合并模块、大重构之前** 写一篇梳理文档，避免凭感觉乱删。

文件命名：`冗余梳理/YYYY-MM-DD-简短主题.md`  
写完后在本文 **实例列表** 加一行链接。

---

## 每条冗余必须按编号写（1、2、3…）

每一条用下面 **7 项**，缺一不可：

```markdown
### 1. [简短标题]

1. **哪里冗余**：文件路径、类名、重复逻辑描述（要具体）
2. **保留危害**：若不动它，继续留着会出什么问题（维护成本、bug 风险、误导）
3. **冗余优化危害**：若删掉/合并，可能破坏什么（调用方、序列化、场景引用）
4. **优化方式**：删除 / 合并到 X / 提取公共 Y（一句话）
5. **代码行数变化**：删 N 行，增 M 行，净 ±K 行（填实际 diff，可估）
6. **性价比**：高 / 中 / 低 — 一句话理由（收益 vs 风险 vs 工时）
7. **结论**：做 / 不做 / 延后（及条件）
```

---

## 性价比怎么判

| 等级 | 建议 |
|------|------|
| **高** | 净减行多、无行为变化、半天内能完、无场景/Prefab 风险 |
| **中** | 要改 2～3 处调用、需回归 UI 或存档 |
| **低** | 牵涉未稳定设计、删了还要加回来、纯臆测的「也许有用」 |

**低性价比默认结论：延后**，除非保留危害已影响编译或上线。

---

## 梳理流程

1. `git diff` 或 IDE 结构视图列出可疑重复
2. 按上表逐条编号（不要合并成一大段）
3. 团队或自己过一遍 **结论** 列
4. 执行「做」的条目，提交后在对应 **模块文档** 更新变更记录
5. 在 [模块索引](../模块索引.md) 如有模块合并则同步

## 示例（格式参考，非真实数据）

### 1. MainUISetup 与 SkillNavItemView 双重 Setup

1. **哪里冗余**：`CreateSkillItem` 内联创建 UI 后 `view.Setup(...)` 与 `Bind` 字段赋值部分重复
2. **保留危害**：改选中样式要改两处，易漏
3. **冗余优化危害**：合并 ctor 时 Editor 脚本需重跑生成场景
4. **优化方式**：保留 Editor 生成，运行时只读序列化引用（生成后不再调 Setup）
5. **代码行数变化**：删 0，增 0（仅流程约定，暂不动代码）
6. **性价比**：低 — 当前仅 Editor 使用，无运行时重复
7. **结论**：延后，等改 Prefab 工作流再做
