# 开发知识库

记录 **已经写进项目里的模块**：文件在哪、怎么用、依赖谁、改时要注意什么。

与设计文档 [设计/](../设计/说明.md) 分离：

| | 设计文档 | 本知识库 |
|--|----------|----------|
| 回答 | 想做什么 | 已经怎么做 |
| 读者 | 策划对齐、方案评审 | 开发、AI 查代码、维护 |
| 更新时机 | 改方案时 | **每做完一个功能必须更新** |

## 维护约定（必做）

### 1. 新功能完成后

1. 在 `知识库/模块/` 新建或更新对应 `模块名.md`
2. 更新 [模块索引.md](模块索引.md) 一行摘要
3. 若涉及设计变更，同步改 `设计/` 下相关文档（只改意图，实现细节留在知识库）

### 2. 模块文档最少包含

- **职责**：这个模块干什么
- **入口**：场景、菜单、主类、Prefab
- **文件清单**：路径列表
- **依赖**：被谁调用、依赖谁
- **扩展**：下次加功能从哪改
- **变更记录**：日期 + 改了什么

### 3. 冗余梳理

代码变多或重构前，对 AI 说 **「冗余梳理」**：按 `.cursor/rules/冗余梳理.mdc` 在对话里列编号清单（现在/应该/净效果/危害 + 文末推荐），**先列清单、用户回编号后再改代码**；不落盘 md。
