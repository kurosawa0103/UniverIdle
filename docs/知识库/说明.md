# 开发知识库

记录 **已经写进项目里的模块**：文件在哪、怎么用、依赖谁、改时要注意什么。

与设计文档 [设计/](../设计/说明.md) 分离：

| | 设计文档 | 本知识库 |
|--|----------|----------|
| 回答 | 想做什么 | 已经怎么做 |
| 读者 | 策划对齐、方案评审 | 开发、AI 查代码、维护 |
| 更新时机 | 改方案时 | **每做完一个功能必须更新正文** |

**过程流水**不写在模块里，写到 [开发日志.md](开发日志.md)。

## 维护约定（必做）

### 0. 动手前

读 [模块索引](模块索引.md) 与本次相关的 `模块/*.md`（Cursor rule：`.cursor/rules/知识库.mdc`）。

### 1. 新功能完成后

1. 更新或新建 `知识库/模块/` 对应文档的**正文**（现状）
2. 更新 [模块索引.md](模块索引.md) 一行摘要（若状态/一句话变了）
3. 在 [开发日志.md](开发日志.md) 追加 **当天** 一节（`## YYYY-MM-DD`）
4. 若涉及设计变更，同步改 `设计/`（只改意图）

### 2. 模块文档最少包含

- **职责**
- **入口**（场景、菜单、主类、Prefab）
- **文件清单**
- **依赖**
- **扩展**（下次从哪改）
- **已知限制**（可选）

**不要**写「变更记录」。历史用开发日志 + git。

### 3. 开发日志

路径：**唯一文件** `知识库/开发日志.md`。按日分节、新日期靠上；同日合并；写结果不写过程。

### 4. 冗余梳理

对 AI 说 **「冗余梳理」**：按 `.cursor/rules/冗余梳理.mdc` 在对话里列清单，**先列后改**；不落盘 md。
